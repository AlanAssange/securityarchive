# Red Team

El red team o equipo rojo es el encargado de conducir pruebas de efectividad en materia de ciberseguridad, simulando ciberataques no destructivos para el sistema de la organización a fin de identificar vulnerabilidades y crear vías de mejora en las operaciones de seguridad.

Las operaciones del equipo rojo dan a las organizaciones una vía de entendimiento hacia los riesgos de seguridad antes de que los atacantes puedan utilizar sus exploits, lo que ayuda a identificar las vulnerabilidades de seguridad.

Usualmente, las pruebas del equipo rojo están ligadas a tiempos determinados. Una prueba puede durar entre semanas a un mes, o más. Cada prueba típicamente empieza con la búsqueda del objetivo del sistema, incluyendo información pública o inteligencia open source.

Luego, el equipo rojo lanza ataques simulados sobre varios puntos en la superficie del sistema, explorando diferentes vectores de ataque. Los objetivos comunes incluyen:

- Sistemas de inteligencia artificial y modelos machine learning
- Datasets que apoyan a la inteligencia artificial y aplicaciones ML.
- Workstations y dispositivos móviles
- Sistemas criptográficos
- Detección de endpoints en sistema (EDR)
- Detección extensiva y respuesta del sistema (XDR)
- Firewalls
- Sistemas de detección de intrusión (IDs)
- sistemas SOAR
- Aplicaciones web y web servers

Durante estos ataques simulados, el equipo rojo irá contra el equipo azul, que actúa como defensor del sistema. El equipo rojo intentará sobrepasar las defensas del equipo azul, y luego dejará registro de las vulnerabilidades que encuentra y qué se pueden hacer con ellas.

El equipo rojo finaliza con una reunión en la que se comparten los hallazgos y recomendaciones para mejoría del sistema.

## Técnicas y herramientas del red team

Algunas de las herramientas y técnicas del equipo rojo incluyen:

Ingeniería social: Utilizan tácticas como phishing, smishing, vishing, spear phishing y whale phishing para obtener información sensible o ganar acceso al sistema corporativo a través de empleados poco suspicaces.

Tests de seguridad física: Controles físicos de seguridad, como sistemas de vigilancia y alarmas.

Pentesting en aplicaciones: Se testean aplicaciones web para encontrar problemas de seguridad (desde errores de código como vulnerabilidades en inyecciones de SQL)

Network sniffing: Se monitorea el tráfico de red para sacar información de un sistema IT como detalles en configuraciones y credenciales de usuario.

Malware en contenido compartido: Se añade malware en drives de red u otros almacenamientos compartidos. Cuando se abren, el código malicioso se corre, permitiendo al atacante moverse lateralmente.

Forzar credenciales: Sistemáticamente se adivina contraseñas de anteriores data breachs, testeando contraseñas utilizadas a través de scripts automatizados.

Continuous automated red teaming (CART)
Red teaming can help strengthen organizational security posture and promote resilience, but it can also pose serious challenges to security teams. Two of the biggest challenges are the cost and length of time that it takes to conduct a red team exercise.

At a typical organization, red team engagements tend to happen periodically at best, which only provides insight into an organization’s cybersecurity at one point in time. The problem is that the business’s security posture might be strong at the time of testing, but it might not remain that way.

Continuous automated red teaming (CART) solutions enable organizations to continuously assess security posture in real time. CART solutions use automation to discover assets, prioritize vulnerabilities and conduct attacks using tools and exploits developed and maintained by industry experts.

By automating much of the process, CART can make red teaming more accessible and free up security professionals to focus on interesting and novel testing.

Benefits of red teaming
Red teaming exercises help organizations get an attacker’s perspective on their systems. This perspective enables the organization to see how well its defenses would withstand a real-world cyberattack.

A simulated attack pits security controls, solutions and even personnel against a dedicated but nondestructive adversary to determine what is—or isn't—working. Red teaming can give security leaders a true-to-life assessment of how secure their organization is.

## Ventajas de tener un red team

- Identificar vulnerabilidades desde donde un sistema puede ser penetrado y un atacante puede ganar acceso.
- Evaluar la seguridad de un sistema ante amenazas reales.
- Identificar y prepararse ante riesgos.
- Priorizar improvements en la seguridad del sistema.

## Pentest vs Red Team

Red team y pentesters son distintos metodos de evaluar un sistema de seguridad. Similar al red team, los pentesters pueden utilizar técnicas de hacking para identificar vulnerabilidades en un sistema. La diferencia, es que el red team está basado en un escenario. El equipo rojo se basa en una franja de tiempo, y utilizan una ofensiva en contra del equipo azul. El objetivo es emular el comportamiento de un adversario real.

Pentest se utiliza sobre un assesment de seguridad mas tradicional. Utilizan diferentes técnicas de hacking para observar cuales funcionan y cuales no. Los pentesters pueden ayudar a las organizaciones a encontrar vulnerabilidades en un sistema. El equipo rojo ayuda a las organizaciones entendiendo como el sistema de defensa se comporta ante ciberataques.
